# 设计:parse-tasks CRLF 修复

## 现有系统分析

`parse-tasks.ts` 以 `md.split('\n')` 切行后用 `TASK_RE`(形如 `/^- \[(x| )\]\s*(.*)$/`)匹配。CRLF 文件每行尾残留 `\r`,而 `\r` 属正则行终止符集合——`$` 语义下 `.*` 无法跨它,`(.*)$` 捕获组实际回退为空/失配,全行不命中 → 0 任务。

## 方案设计

### 方案 A:行切分归一(选定)

`md.split('\n')` → `md.split(/\r?\n/)`。单点修复,不动正则本身(其语义在 LF 行上正确)。

**不做**:不改 `TASK_RE` 本身;不动 align change 刚落的 🔧[人工] 口径逻辑(其前缀匹配用 startsWith,天然不受 `\r` 影响?待实施时确认 `trim` 顺序,若有漏一并钉住)。

## 接口 / 数据契约

无变化。

## 实施步骤

1. TDD:CRLF/混合行尾单测先红
2. 一行修复至绿
3. 回归

## 风险与 Trade-off

- 风险:无(纯输入归一)
- 开放问题:无

## 测试策略

- **单元**:CRLF 全文 / LF+CRLF 混合 各一,断言与 LF 基准结果一致(含 🔧[人工] 条目场景)
- **回归**:`pnpm typecheck && pnpm test` 全绿(基线既有环境失败除外)
